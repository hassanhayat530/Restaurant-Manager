A console-based restaurant management simulation written in Java. The application allows a user to manage tables, place and process orders, track kitchen workflow, and generate billing receipts — all through an interactive console menu.

Architecture Overview

The project is divided into three packages, each with a distinct responsibility:

  • model — Plain data classes representing the core entities of the simulation: tables, orders, order items, and menu items. Also contains the enumerations {@code TableStatus} and {@code OrderStatus} which define the lifecycle states of tables and orders respectively.
  • management — Service classes that coordinate business logic. {@code TableManager} owns the collection of tables and enforces seating rules. {@code KitchenQueue} maintains a FIFO queue of pending orders. {@code OrderProcessor} moves orders through the kitchen pipeline. {@code BillingService} calculates totals, applies tax and tip, and prints receipts.
  • ui — The console entry point. {@code Main} drives the interactive loop, reads user input, and delegates all actions to the management layer.

Order Lifecycle

Every order progresses through four states defined by {@code OrderStatus}:

  1. PLACED - the order has been taken and is waiting in the kitchen queue.
  2. IN_KITCHEN - the order has been picked up and is being prepared.
  3. READY - the order has been prepared and is ready to be served.
  4. SERVED - the order has been delivered to the table and is ready to be billed.

Orders cannot skip states. Each transition is enforced by {@code OrderProcessor} and any attempt to advance beyond {@code SERVED} throws an {@code IllegalStateException}.

Running the Application

Build and run the project using Maven: 

    mvn package
    java -jar target/restaurant-management-1.0.jar

See {@code user-documentation.md} for a full walkthrough of the console interface and a complete example session.
